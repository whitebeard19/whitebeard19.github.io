## The double charge

A customer taps Pay. Your server charges the card, but the response dies somewhere in a lift with bad signal. The app sees a timeout and retries. Your server, having no memory of the first attempt, charges again.

The fix is to make the request **idempotent**: doing it twice has the same effect as doing it once. The client sends a unique key with the request, and the server remembers what it did for each key.

```sh title="terminal"
curl -X POST /charge \
    -H "Idempotency-Key: 8e1f-…-c2a7" \
    -d '{"amount": 49900}'
# {"id":"ch_19x","status":"succeeded"}
```

## The server side

Store the response under the key. If the key shows up again, replay the stored response instead of doing the work twice.

```ts title="checkout.ts" {3-4}
app.post('/charge', async (req, res) => {
  const key = req.header('Idempotency-Key');
  const seen = await redis.get(`idem:${key}`);
  if (seen) return res.json(JSON.parse(seen)); // replay

  const charge = await psp.charge(req.body);
  await redis.set(`idem:${key}`, JSON.stringify(charge), 'EX', 86400);
  res.json(charge);
});
```

## The race you'll hit

If two retries arrive at the same moment, both can miss on line 3 and both charge. Claim the key atomically first:

```diff lang="ts" title="checkout.ts"
-  const seen = await redis.get(`idem:${key}`);
+  const won = await redis.set(`lock:${key}`, '1', 'NX', 'EX', 30);
+  if (!won) return res.status(409).json({ retry: true });
+  const seen = await redis.get(`idem:${key}`);
```
