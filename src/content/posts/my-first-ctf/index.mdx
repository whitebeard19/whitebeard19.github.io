## Looking around

A CTF challenge usually hands you something small: a login page, a file, a snippet of code. The first job is just to read carefully. One challenge gave a login form and this hint in the page source:

```html title="view-source"
<!-- TODO: move the test login out before launch -->
<!-- creds in /static/notes.txt -->
```

That comment is the whole lesson: things you leave in "for now" are the first thing a stranger reads. I've written comments exactly like this at work. I won't again.

## Reading a file as bytes

One challenge gave a file with no extension. Opening it as raw bytes (a "hex dump") shows what it really is. The first four bytes, the "magic number", name the format. A little further in, a ZIP also writes down the name of the file packed inside it. Hover or tap any byte:

## The one that beat me

A crypto challenge used a cipher I didn't recognise. I couldn't solve it in time. After the event I read other people's writeups and learned what I'd missed. The takeaway is hidden below, so you can guess first:

<Spoiler label="SPOILER · click to reveal what I learned">
It was a classic substitution cipher with a repeating key (a Vigenère). The lesson: repeating keys leave repeating patterns, which is why real systems use vetted, modern crypto libraries instead of inventing their own.
</Spoiler>

<Hat role="DEV HAT">
Every one of these taught me a defence I now use in real code: check what a file actually is, not what its name claims; never ship debug comments; and never roll my own crypto.
</Hat>
